# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

UX/UI iteration generator: give a PRD/brief + direction, get back a few
distinct low-fidelity + high-fidelity static HTML mockups. No build step for
the mockups themselves — every one is plain self-contained HTML opened via
`file://`. (`scripts/` has its own `package.json`, for Playwright only.)

## Structure

```
features/<feature-slug>/
  brief.md              # the PRD/direction as given
  reference/             # optional: screenshots, existing designs to riff on
  iterations/
    v{n}-<angle>-lofi.html   # grayscale wireframe tier
    v{n}-<angle>-hifi.html   # branded, production-real tier
    index.html               # tabs + iframe viewer for all variants, generated from a shared template
```

## Starting from an idea, not a brief (generate-brief skill)

Triggered when someone wants to start a new feature but doesn't have a
written brief/PRD yet — interviews them for the essentials (what it is, who
uses it, must-include content, tone, brand, reference) and writes
`features/<slug>/brief.md`. Skips straight to writing if a complete brief is
already pasted. Never auto-chains into `generate-ui-iterations` — always
asks first, since the user may want to add reference images before
generating.

## Core workflow (generate-ui-iterations skill)

Triggered whenever given a brief/PRD and asked for mockups/iterations/directions.
Full steps live in `.claude/skills/generate-ui-iterations/SKILL.md` — key points:

- Default **3 variants**, each at **two fidelity tiers** (lofi + hifi) unless
  the brief asks for a single tier.
- The N creative angles are chosen by the orchestrating agent itself, up
  front — never punted to subagents, since they can't see each other's work
  and would converge on the same layout.
- Each variant (angle × tier) is generated by a separate `Agent` tool call,
  all dispatched in parallel in one message (2N agents total). Each agent
  gets the full brief, resolved tokens, its one angle as a concrete brief,
  its tier's rules, and its exact output path — fully self-contained.
- `index.html` is never hand-rolled per feature — copy
  `.claude/skills/generate-ui-iterations/templates/index-template.html`
  verbatim and fill in the title/subtitle/`ANGLES` array. Edit the template
  itself if the index UI needs to change, so all features stay in sync.
- Re-running for an existing slug (e.g. "2 more directions") appends
  `v{n+1}-...` files and regenerates `index.html` — never overwrites prior
  variants.
- Retrofitting lofi/hifi onto legacy untiered `v{n}-<angle>.html` files: read
  the existing file as the structural baseline (don't regenerate from
  scratch), keep the old file on disk as legacy, don't delete without asking.

## Design tokens (design-system-tokens skill)

Mockups read literal token values from whatever CSS custom-property sheets
are in `tokens/`:

```
tokens/default.css     # brand-neutral fallback, ships with the repo
tokens/<yours>.css      # drop your own design system here, any prefix
```

The skill infers the token prefix from the file rather than assuming one,
resolves up to 3 hops of `var()` indirection, and hands subagents literal
hex/rem/font-stack values — semantic token *names* mean nothing in a
standalone HTML file with no build step. If a category is missing it falls
back to `default.css` for that category and says so; if `tokens/` is empty it
uses neutral system defaults and says so. It never substitutes a brand
palette from memory.

## Screenshotting iterations

```bash
cd features/<slug>/iterations && mkdir -p screenshots
for f in v*.html; do
  node ../../../scripts/screenshot.js "file://$PWD/$f" "screenshots/${f%.html}.png" 1
done
```

Desktop viewport (`1280,900`) by default; narrow only for an explicitly
mobile-only brief. Glob is `v*.html` on purpose to skip `index.html`. After
generating, `Read` the PNG to confirm
real content rendered (not a blank page from a dead `<img>` src or JS error).
Prerequisite: `cd scripts && npm install` once. First-run fix if Playwright's
browser binary is missing: `npx --yes playwright install chromium`.
