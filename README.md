# ux-explorations

UX/UI iteration generator: give a PRD/brief + direction, get back a few
distinct low-fidelity and high-fidelity static HTML mockups. No build step
for the mockups themselves — everything is plain self-contained HTML opened
via `file://`. Bring your own design tokens, or use the neutral fallback.

Not technical? Start with [`GUIDE_FOR_NON_TECHNICAL_USERS.md`](GUIDE_FOR_NON_TECHNICAL_USERS.md) instead — this README assumes you're comfortable in a terminal.

## Quickstart

This repo is designed to be driven through Claude Code chat, not by hand-writing files. Open the repo in Claude Code and:

**No brief yet?**
> "I want to design a checkout confirmation page, no brief written yet."

Claude interviews you (what it is, who uses it, must-include content, tone, brand, reference) and writes `features/checkout-confirmation/brief.md`. It stops there and asks before generating anything — add reference screenshots to `features/checkout-confirmation/reference/` first if you have them.

**Have a brief already?**
> "Here's the brief for checkout confirmation: <paste>. Generate 3 directions."

Claude picks 3 distinct creative angles itself, then generates lofi + hifi HTML for each (6 files total) in parallel, plus `features/checkout-confirmation/iterations/index.html` to browse them all.

**Want more directions later?**
> "Generate 2 more directions for checkout-confirmation, maybe darker/moodier."

This appends `v4-...`, `v5-...` files and regenerates the index — it never overwrites or deletes prior variants.

## How it works

1. A brief captures what's being designed: what it is, who uses it, must-include content, tone, brand, reference material.
2. Claude picks a few (default 3) distinct creative angles up front — this has to happen in one place with full context, not be split across subagents, or they'd converge on the same layout with no visibility into each other's choices.
3. Each angle × fidelity tier is generated by its own agent call, all dispatched in parallel, each given the full brief, resolved design tokens, its one angle, its tier's rules, and its exact output path.
4. Fidelity tiers, per variant:
   - **lofi** — grayscale wireframe, for checking layout/flow before anything looks "finished"
   - **hifi** — production-real polish, using literal values from your design
     tokens in `tokens/` (a brand-neutral fallback ships with the repo)
5. `index.html` ties every variant together in tabs, generated from a shared template rather than hand-rolled per feature, so the viewer UI stays consistent across all projects.

## Structure

```
features/<feature-slug>/
  brief.md                       # the PRD/direction as given
  reference/                     # optional: screenshots, existing designs to riff on
  iterations/
    v{n}-<angle>-lofi.html       # grayscale wireframe tier
    v{n}-<angle>-hifi.html       # branded, production-real tier
    index.html                   # tabs + iframe viewer, generated from a shared template
```

## Skills (`.claude/skills/`)

Claude picks these automatically based on what you ask for — you don't invoke them directly.

- **generate-brief** — interviews you to turn a loose idea into `features/<slug>/brief.md`. Never auto-chains into generating mockups; always asks first, since you may want to add reference images before generating.
- **generate-ui-iterations** — the core brief → mockups workflow described above. Default 3 variants × 2 tiers unless the brief asks for a single tier.
- **design-system-tokens** — reads literal color, spacing, radius, and type values from any CSS custom-property sheet in `tokens/`, instead of guessing. Drop your own design system in that directory (any filename, any token prefix) and it's picked up with no skill edits; `tokens/default.css` is a small brand-neutral fallback.
- **screenshot-iterations** — drives Playwright to screenshot every variant at a desktop viewport for quick visual review without opening each file by hand.
