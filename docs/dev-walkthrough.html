🛠️ Dev walkthrough

🎯 The idea

It's a design sprint, minus the sprint.

A design sprint normally means days in a room: diverge into a few genuinely different concepts, sketch each one, then build a single prototype to react to. The diverging and the sketching stay. The days don't. Feed in a brief, N agents each take one distinct direction in parallel, and real HTML comes out the same afternoon.

Every direction ships at two tiers: lofi is the grayscale wireframe, no color, boxes standing in for icons, just the layout argument. Hifi is the real thing: brand color, type, copy, photos. Both come out of the same run, and it's just HTML you open straight in a browser.

features/<feature-slug>/ brief.md # the PRD/direction, as given reference/ # optional: screenshots, existing designs iterations/ v1-<angle>-lofi.html # grayscale wireframe v1-<angle>-hifi.html # branded, production-real index.html # tabs + iframe viewer export/ # zip + side-by-side PDF
🧩 Architecture

Three pieces, not a framework

Just three kinds of file, each doing exactly one job, small enough to read in five minutes and understand the whole system.

Skill
A markdown file of instructions: Claude Code reads it and just... follows it. This is where the judgment calls live: picking angles, writing a brief.
.claude/skills/generate-ui-iterations/SKILL.md
Script
Actual code, for once. A skill shells out here for the mechanical stuff that shouldn't be re-reasoned about every time: taking a screenshot.

Template
A static file, copied as-is and filled in with this feature's title and angles. Keeps every feature's viewer looking the same instead of rebuilt from scratch each time.

⚙️ How it works

generate-ui-iterations, step by step

This is a "skill": a markdown file of instructions that Claude Code follows by name. Runs once per brief. Steps 3 and 4 are the ones that decide whether you get real directions or three recolors of the same one.

1
Write the brief
Kebab-case slug, brief.md saved verbatim. Defaults to 3 variants × 2 tiers unless the brief says otherwise.
2
Pull real design tokens
Reads literal color, spacing, and type values from any design-token CSS in tokens/ — your own, or the neutral fallback that ships with the repo.
3
Pick N angles
Done once, up front, by the orchestrator, never handed to the agents that build the mockups.
Why: those agents run at the same time and can't see each other's work. Hand them the angle choice and you'd get three recolors of one layout. So the orchestrator decides up front, every time.
4
Fan out 2N agents, in parallel
One agent per angle × tier, all dispatched in a single message. Each gets the full brief, resolved tokens, its one angle, and its exact output path, nothing else.
5
Build index.html
Same shared template every time, just filled in with this feature's title and angles. Nobody writes this file from scratch per feature.
6
Report back
File paths + one line per angle.
📋 Example

What a real brief actually looks like

features/analytics-dashboard/brief.md (verbatim, trimmed for space)
How Might We
How might we let an ops/growth team notice something worth acting on within the first five seconds of opening the dashboard, instead of having to read every chart to find the one that moved?
Requirements
  • Four core metrics, each with a daily 30-day series: signups, activation, MRR, churn
  • At least one metric must visibly show an anomaly — the "why did that happen" moment
  • All charts hand-authored inline SVG, hardcoded data — no chart-library CDN
  • Lofi tier differentiates series by shape/dash/label, not color alone
Fidelity & scope for this round
Two tiers per direction, this repo's default: lofi (grayscale wireframe) and hifi (production-real, resolved token values). 3 directions.

🔍 Good to know

A few things worth knowing before you try it

Plain HTML, no build
No build step: every mockup is one file you can open with a double-click.
Re-running never overwrites
Ask for "2 more directions" and it appends v{n+1}-... files and regenerates index.html. Old variants stay right where they were.
Defaults are just defaults
The brief's own words win. The example brief you just saw said "lofi only, 5 variants," and that's exactly, only, what it got.
Reference materials actually get used
Screenshots or existing designs dropped in a feature's reference/ folder get read by the agents building the hifi tier, not just filed away.
